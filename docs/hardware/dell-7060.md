# Dell OptiPlex 7060 Micro

El Dell es el recurso de cómputo más potente del laboratorio inicial y por eso se reserva para virtualización.

## Prioridad de upgrades

Para un host Proxmox con varias VMs, **la RAM suele convertirse antes en limitante que el CPU**. El orden de mejora recomendado es:

1. ampliar RAM;
2. medir I/O y ocupación real de los SSD;
3. recién entonces decidir reemplazo de M.2 o SATA.

No se cambia almacenamiento solo por capacidad teórica si todavía cumple rendimiento, salud y espacio disponible.

## Distribución inicial orientativa

Con 16 GB se debe comenzar conservadoramente:

| Componente | vCPU | RAM | Disco | Comentario |
|---|---:|---:|---:|---|
| Proxmox host | — | reservar ~2 GB+ | sistema | no sobreasignar memoria al principio |
| VM Core Docker | 2 | 4 GB | 40–80 GB | DNS auxiliar, n8n liviano, dashboards |
| VM DevOps | 2 | 4 GB | 80–150 GB | solo si se necesita |
| VM k3s | 2 | 4 GB | 40–80 GB | laboratorio, no siempre encendida |

Total presupuestado con las 3 VMs simultáneas: **14 GB de 16 GB**, dejando ~2 GB de margen para el host. Esto es ajustado: **no alcanza para una cuarta VM dedicada a observabilidad** (Prometheus/Grafana/Loki, ver [inventory/services.yaml](https://github.com/rudemex/oscar-homelab/blob/main/inventory/services.yaml)). Mientras el Dell tenga 16 GB, el stack de observabilidad corre **dentro de `core01`** (como contenedores Docker adicionales, no como VM propia) — ver [instalación del stack de observabilidad](../observabilidad/instalacion-stack.md). Recién con la ampliación de RAM (32/64 GB) tiene sentido separarlo en su propia VM.

Con 32/64 GB se puede separar más funciones y mantener varios entornos activos, incluyendo una VM de observabilidad dedicada.

## Storage propuesto

Una estrategia inicial simple:

- M.2: Proxmox + discos de VMs sensibles a I/O;
- SATA SSD: datos, artefactos, volúmenes o backups temporales;
- NAS futuro: backups y datos compartidos.

Esto debe ajustarse a la salud SMART y al tamaño real de cada workload.

## Métricas a observar antes de comprar hardware

- RAM usada y swap;
- CPU ready/steal y load;
- latencia de disco;
- IOPS;
- ocupación por datastore;
- temperatura;
- crecimiento mensual.

Comprar después de medir evita mejorar el componente equivocado.
